Data handling

Privacy policy

Last updated: October 9, 2026

MailBridge is a personal application operated by its owner on a private Windows host. It has no public registration. This policy describes the application and these information pages.

Google account access

The owner chooses which Gmail accounts to connect and approves access through Google. MailBridge requests the Gmail modification permission, gmail.modify. This permission is broader than read-only access.

The implemented features read mail, add MailBridge labels, and save a draft when the owner explicitly requests it after review. The application does not send mail, delete messages, or unsubscribe from mailing lists.

An initial scan looks for recent messages, excluding spam, trash, and drafts. Later synchronization uses Gmail changes. This scan window is not a storage deletion schedule.

Data stored on the Windows host

  • Connected account details, Google access and refresh tokens, and synchronization state.
  • Message identifiers, sender and recipient details, subjects, extracted body text, timestamps, and message flags.
  • Analysis results, summaries, suggested replies, reminder state, and records of requested actions.
  • Paired device information, notification tokens, and notification status.

Attachment content is not analyzed, and links in messages are not opened. The application can record that an attachment or link is present. Extracted text and thread context have size limits, so analysis may omit information.

Database record values are encrypted using Fernet before storage in SQLite. Account and message lookup keys use HMAC. Record types, some opaque identifiers, record counts, and timing information remain visible. Host configuration contains credentials and encryption keys protected by Windows file permissions; it is not itself encrypted by this database mechanism.

The owner controls access to the computer and any backups. A person with access to the host and its keys may be able to read stored content. The iPhone stores pairing credentials in the device Keychain and displays data retrieved from the host.

Hosted Claude analysis

MailBridge sends message subjects, body text, message timing and flags, and selected same-thread context to Anthropic's hosted Claude service to generate categories, summaries, follow-ups, and proposed replies. This is online processing outside the Windows host.

The analysis input does not deliberately include OAuth credentials, provider message identifiers, or separate address-header fields. Message text itself can contain names, addresses, confidential information, or other personal data. MailBridge does not automatically redact that text.

The owner must keep Claude's model-improvement setting off before enabling this analysis. MailBridge does not enforce or verify that provider account setting. Anthropic describes the control in its model-improvement settings guidance.

Opting out of model improvement does not mean zero retention or no provider review. Anthropic's training policy describes exceptions, including safety-flagged interactions. Its retention policy governs how long it may keep data, including safety and legal exceptions. Disabling local Claude session persistence does not control Anthropic's server-side retention.

Phone connection and notifications

The iPhone accesses the Windows host through an owner-configured private HTTPS connection using Tailscale. Tailscale supplies network connectivity; its privacy policy describes service data it processes. A private connection does not prevent content sent separately to Google or Anthropic from reaching those providers.

If notifications are enabled, Apple Push Notification service receives a device token, a generic attention notice, and opaque item and notification references. The notification payload contains no email subject, sender, or body. Opening the app retrieves details from the host. Apple's handling of service information is described in its privacy policy.

Retention and removal

MailBridge has no automatic expiry or purge schedule for stored mailbox records and analysis. Data remains on the Windows host until the owner removes it. Marking an item handled, reading a message, or removing a phone pairing does not erase stored mailbox data.

The owner can stop future Google access by revoking MailBridge in Google Account connections. Revocation does not erase local records or remove labels and drafts already created in Gmail.

To remove MailBridge's local data, the owner must stop the host processes and remove the application's database, its associated database journal files, and any retained backups. Protected configuration and keys must also be removed when decommissioning the host. MailBridge does not provide an automatic full-data deletion control. Provider-held copies are subject to the provider's own retention and deletion controls.

Other uses and these pages

MailBridge has no advertising, sale-of-data, or model-training feature. Mail data is used for the review, organization, reply preparation, and notification functions described here. Google account data is also subject to the Google API Services User Data Policy and the Google Workspace API user data policy.

These information pages have no sign-in form, analytics script, or tracking cookies set by MailBridge. The website hosting provider may receive ordinary request information, such as an IP address and browser details. These pages do not connect to the owner's MailBridge host or access Gmail.

Questions and changes

For privacy questions, use the support email shown on MailBridge's Google authorization screen. Changes to application data handling should be reflected here before the changed behavior is used.
